# Novo projeto: sempre planejar antes

Regra do Ronaldo: nenhum projeto novo começa direto no código, nem quando o pedido parece simples ("só um app rápido de X" também merece plano).

1. Resuma o objetivo e o público do projeto em 1-2 frases — confirme que entendeu antes de seguir.
2. Levante as decisões técnicas que precisam ser tomadas antes de codar (stack, hospedagem, banco de dados, autenticação, integrações externas) e pergunte quando a resposta não for óbvia — não assuma.
3. Escreva um plano curto cobrindo: estrutura de pastas, principais telas/funcionalidades do MVP, e ordem de implementação. Use o modo de planejamento (EnterPlanMode) quando disponível.
4. Só comece a escrever código depois que o plano for aprovado.

Não pule essa etapa achando que "dá pra ajustar depois" — o plano existe pra pegar decisão errada antes de virar código, não depois.
